# 规则与解释

| 观察 | 处理与修复方向 |
|---|---|
| 初始空H1、就绪后补全 | 记录正常补全；不直接称缺H1 |
| 主体/占位/实体未就绪 | evidence_gap；超时保持未知，检查接口与模板信号 |
| 用户可见Load failed | ui_observation；核对路由、业务参数、接口和错误页状态，不用普通控制台警告替代 |
| 渲染前后title/canonical/schema/链接变化 | 保存双方值和采集关系；原始请求独立时不直接作因果判断 |
| 元信息节点或完全相同schema块增加 | rendering_review；检查组件挂载/卸载和重复注入。同@id不同属性不自动判重复 |
| 同URL不同进入路径稳定字段不同 | rendering_review；检查SSR、异步实体数据、路由监听和head更新时机 |
| 操作后URL/实体不符 | interaction_review；先核对期望与实际跳转、旧组件或返回缓存，合法跳转不能一律判错 |
| 分页变化URL不变 | 无路由策略为候选；有明确策略才判policy_conflict |
| 任意证据缺失或截断 | 保留缺口，不归入“网站错误”数量 |

每个问题按005、规则、URL、进入方式生成稳定ID；一轮同ID合并证据，重复运行同内容不重复计数，缺席不自动关闭。历史库供后续017修复验收使用。

不判断搜索引擎最终是否索引，不保证某种改动提升排名。浏览器UI结果不是Googlebot结果。标题缺词的路径差异应检查元信息随业务数据更新，而不是只把所有模板写成同一静态标题；canonical目标错误由004检验内容等价与路由策略后修正。

参考：[Google JavaScript SEO基础](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics)介绍抓取、渲染与索引的区别及元信息、canonical和可发现链接的注意事项。检查日：2026-09-17（Asia/Singapore）。
