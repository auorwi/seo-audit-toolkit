# 飞书交付

默认交付本地 Markdown 问题清单。本参考仅在用户明确要求飞书发布且指定或确认目的地时适用；此时使用当前可用 `lark-doc` 技能/文档工具。先读对应创建/编辑、XML及回读说明。无需发送消息，不修改分享权限或所有权。用户指定现有文档时更新该文档；用户明确要求新建时，在其指定或确认的空间创建并保存返回URL/token。目的地缺失时先保留可审阅的本地清单，再补齐目的地，不自动创建远程文档。

## 内容合同

- 顶部只写检查页面数；每页为页面名、URL 和一份问题清单。
- 用原生 `<checkbox done="false">`，每项一句短中文，只描述具体标签问题。默认不加修复方案、复测步骤、工具状态、日志或其他专项问题。
- 如“缺少 meta description”“A 标签使用 javascript: 跳转”“UL 子元素未使用 LI”“H2 下直接使用 H4”。示例不是实际发现；须有本页浏览器证据。
- 相同问题合并，不同问题保留。无问题页简写，未完成页说明，不能漏页。
- `report.feishu.xml` 是初稿；发布前逐条确认属于常见标签检查，并压缩为上述格式。工具原始结果保留在本地，不直接发布。

## 发布与验证

短报告可一次创建；大量页面先建页标题骨架，再由主Agent按页顺序插入内容，遵循块ID生命周期。不要因长度限制删除页面或问题。CLI `@file` 使用当前工作目录下相对路径，不把页面文字拼到shell代码中。

```bash
# 具体参数以当前 lark-doc 帮助为准；在报告目录运行
lark-cli docs +create --as user --content @report.feishu.xml
lark-cli docs +fetch --as user --doc "<RETURNED_DOC_URL>" --detail full
```

写入后回读，核对全部URL及页数、各页问题类别、checkbox数量和未勾选状态、未完成页、首尾页。长文按页回读后整体对账。只有写入成功且回读一致才交付链接；XML文件或离线测试不是飞书发布成功。

把返回URL/token、scope_id、报告内容校验值、发布时间和回读结果写入数据目录的 `publication.json`。重试前先读已创建文档，避免重复创建；响应不确定时查已有文档再处理。重跑有人勾选的报告时保留人工状态/备注：创建新轮次文档并链接旧轮次，或针对明确变化局部更新，不整篇覆盖人工勾选。

工具缺失、鉴权失效、权限不足或接口失败：完成本地报告与待发布清单，明确飞书交付未完成及实际错误，只请求必要授权/目标信息。不改用消息发送，不虚构链接，不声称最终交付已完成。
