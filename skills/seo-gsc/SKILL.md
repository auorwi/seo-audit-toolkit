运行前设置 `SEO_SITE_PROFILE=/absolute/path/site.json`。使用 `seo.py init` 为目标站点创建显式配置；主机采用精确白名单，不自动扩展子域。默认使用通用网站规则；`business_profile: "bingx"` 为可选业务扩展，只有明确选择它才启用对应路由和市场参考逻辑。缺少 profile 时不进行线上采集。

默认交付本地报告或问题清单。只有用户明确要求外部发布并指定或确认目的地时，才调用相应飞书/外部工具写入；无需发布时不要求外部账户授权。所有输出、证据和状态库存放在技能目录之外，按站点隔离。示例、fixtures 和既有历史记录仅用于显式选择的离线演练，不自动导入真实报告。浏览器的通用就绪信号仅证明可见正文与有限稳定性，不证明业务实体正确；如提供身份/模板信号则保持这些更强要求。


# 目标网站 014 · Google Search Console

独立入口：只运行 GSC 范围；用户指定 URL/报告时按指定范围，否则先读取当前平台报告，再按问题类型、主机、语言、模板和业务重要度选样。全量后台计数、可见样例与实际逐页核验数量分别列出。不要把模板抽样说成全站逐页检查。

本技能由 Codex 操作已授权浏览器或可用只读 API 采集，再用 Python 验证、关联和去重。脚本本身是证据审查器，不负责 OAuth 登录或调度。运行需要 Python 3.10+ 和同级已安装的 `seo-crawlability`（共用身份、证据时间和问题历史模块）。真实平台读取受登录、配额和可用工具约束。

## 采集与核验

1. 先读 [采集流程](references/collection.md)，确认 `sc-domain:example.com` 或明确的 目标网站 URL-prefix property。域名资源可能包括测试/服务子域；保留主机，不把其全部排除算作主站流量损失。先记录 property、筛选、统计单位、报表日期和本次采集时间。
2. 登录态浏览器可读时直接读取。缺少 OAuth 不必阻止浏览器模式；遇到登录、验证码或锁屏交由用户处理，同时继续可独立完成的工作。不要访问个人浏览器数据库、导出会话认证或绕过设备锁定。API 仅在已有授权凭据/连接器可用时调用官方只读端点。
3. 保存原始 API JSON 或浏览器可见文本/导出；截图作补充。读 [证据合同](references/evidence.md) 生成带 SHA256 的输入。UI 枚举映射必须由实际读取者逐字段对照原文；哈希只证明字节未改变，不证明摘录真实或语义映射正确。不得用过去的审查结论重新伪装成当前后台快照。
4. 对每个选定 URL 读取 URL Inspection 索引快照，并以同一完整 URL、设备采集当前线上 HTTP/浏览器证据。保留查询参数、跳转目标、最后抓取时间；遇到语言/实体落点变化，先转 004/005 复核。普通浏览器或 HTTP 观察不是 Googlebot 实测。Google UI 的 Live test 是另一个证据来源，也不证明已收录。
5. 按 [问题归属](references/routing.md) 运行需要的专业技能；仅调用与本次问题相关的技能，不顺带执行全库。GSC 原因不等于根因；有当前专业证据才能标明底层缺陷复现，推测则明确待确认。将专业技能报告链接到平台观察，不重复创建同一底层修复工单。
6. 运行审查器，检查未关联、设备不符、证据过期、配额/权限不足与未核验样例，再输出问题、证据、修复方向、负责专业、复测方式和覆盖分母。搜索表现对比只接受等长、非重叠、同筛选与聚合、完整数据窗口；缺失行不按零处理。

```bash
python3 <skill-dir>/scripts/audit_gsc.py \
  --manifest <run-dir>/manifest.json \
  --state <persistent-state-dir>/gsc \
  --output <new-report-dir>
```

`--at` 可指定重放时间；历史重放必须明确标注，不能当作新巡查。默认采集有效期 24 小时，可用 `--max-age-hours` 调整并披露原因；不要为了消除缺口擅自拉长。

退出码：0=声明范围的索引快照与 HTTP 对照完成，2=有证据缺口但报告已生成，1=输入或执行错误。0 不代表全站健康或完整技术 SEO 检查通过。报告目录必须新建，避免覆盖原证据；持久 `--state` 保持不变以支持跨周去重。

## 输出与边界

交付 `report.md`、`report.json`、`checks.json`、`findings.csv`、`issue-history.*`、`referrals.json`；JSON 保留原始证据位置、哈希、平台与当前观察时间。人类报告说明哪些专业核查真的执行、哪些只是转交待查，不能把转交列表写成已完成。

- `engine_observation` 是索引/报表观察；`live_test_observation` 是 Google 实时测试观察；同一原因兼有两种来源时保留各自证据，标记 `mixed_platform_observation`。`requires_intent_review` 需先确认页面是否应该被索引。这些分类均不自动证明根因。
- 相同 property、URL、报告和规则保持问题 ID；重复相同证据不新增发现记录。新一周更新观察历史；本轮没有出现、验证 Passed、当前 200 或 Live test 可用均不自动关闭。修复验收交给 017。
- 请求索引、Validate fix、提交/删除 Sitemap、修改 robots/canonical/线上页面不属于本技能只读审查步骤。
- 发布飞书报告属于后续报告技能 018 或用户当次明确要求的文档操作；没有执行发布时只交付本地产物，不能声称已同步。
- 本技能没有总入口，也没有自动创建周计划。需要定时任务时按用户明确要求配置。

官方能力边界和参考链接见 [采集流程](references/collection.md)。本地可执行测试：`python3 -m unittest discover -s <skill-dir>/tests -v`。
